## The shift from writing code to describing intent

For decades, building software meant learning a programming language, memorising framework APIs, and fighting with build tools. **Vibe coding** flips that model: you describe what you want in natural language — a "vibe" — and an AI agent generates, runs, and iterates on the code for you in real time.

The term was coined by Andrej Karpathy in early 2025 and has since exploded into an entire product category. Tools like SprintBuild, Lovable, Bolt, and Replit Agent all implement versions of it.

## How vibe coding works on SprintBuild

1. **You describe your app** — "Build me a habit tracker with streaks, dark mode, and a weekly summary email."
2. **The agent picks a stack** — Next.js, Tailwind, Supabase, whatever fits the brief.
3. **Code is generated in a sandbox** — you watch files appear in a live file explorer.
4. **A preview renders instantly** — the running app shows up beside the chat.
5. **You iterate conversationally** — "Make the streak badge pulse when it hits 7 days."

No terminal commands. No dependency hell. No context-switching between docs tabs.

## Who is vibe coding for?

- **Founders** who want to validate an idea in hours, not sprints.
- **Designers** who can describe UI but don't want to fight CSS.
- **Developers** who use it as a turbo-scaffold, then take over the code.
- **Students** learning by seeing real code generated from intent.

## When NOT to use it

Vibe coding excels at greenfield apps, prototypes, and internal tools. It's not a replacement for careful architecture on large-scale systems where you need deterministic control over every line. Think of it as a pair-programmer that's incredibly fast at first drafts.
